# Feedline

Offline-first RSS reader for Android (`com.vempus.feedline`), built with Expo and React Native. No backend; light theme only.

## Expo

- Expo APIs change every SDK. Check the `expo` major in `package.json`, then read `https://docs.expo.dev/versions/v<major>.0.0/` (index: https://docs.expo.dev/llms.txt) rather than working from memory.
- Add dependencies with `npx expo install`.
- `android/` is generated by prebuild. Change native config only through `app.json` and `plugins/`.
- No EAS; everything builds locally.

## Done means

`npx tsc --noEmit && npx tsc -p __tests__ --noEmit && npx eslint src __tests__ plugins && npx jest`. Verify UI changes on the real phone; no emulator.

## Build and phone

- Run `npm run build:apk` in the background (about 10 minutes). It writes `dist/release/`: `feedline.apk` (arm64), `feedline-armv7.apk` and a `.sha256` for each.
- Signing uses `FEEDLINE_RELEASE_*` in `~/.gradle/gradle.properties`. The script rejects any other key, because a different key can't update installs. Never commit the keystore or passwords.
- Phone: a Pixel 7a over USB, arm64 only. adb is in `/opt/homebrew/share/android-commandlinetools/platform-tools`. Screens are 1080×2400; scale tap coordinates exactly.
- Undo test side effects: opening an article marks it read, and test feeds need removing.

## Releasing

GitHub Releases is the only channel. Commit as `deepakness <me@deepakness.com>`.

1. Bump `version` and `android.versionCode` in `app.json`. versionCode only goes up; 1.0.0 is 10.
2. Add a `CHANGELOG.md` entry.
3. Run the checks, build, and test on the phone. Then commit and push; CI must pass.
4. Run `git tag vX.Y.Z && git push origin vX.Y.Z`, then `gh release create vX.Y.Z dist/release/* --title "Feedline X.Y.Z" --notes-file <notes> --latest`.
5. Run `npm run build:aab` and upload `dist/play/feedline.aab` to the Play Console. The AAB never goes on GitHub.

- Play: the app is on the Vempus organisation account. Play App Signing holds a copy of the Feedline key, so Play and GitHub builds update each other. AABs are signed with a separate upload key (`FEEDLINE_UPLOAD_*` in `~/.gradle/gradle.properties`); the script rejects any other.
- Asset names are fixed. The README links `releases/latest/download/feedline.apk` and `feedline-armv7.apk`.
- Users read release notes in the app (Settings → Follow Feedline updates subscribes to `releases.atom`), so write them for people.
- Rewrite history only when the owner asks: one orphan commit, force-push, then delete the old release, tag and CI runs.
- Icons come from `scripts/make-icons.py`. The social image comes from `scripts/make-social-preview.py`; the owner uploads it in GitHub Settings. For screenshots, demo mode doesn't hide notification icons, so paint over them.

## Non-obvious design

- All DB writes go through `write()` / `writeTransaction()`, then `notifyChange`. Lists read via `useQuery`, which keeps row identity so memoized rows don't re-render.
- Migrations are append-only. `articles_fts` is trigger-synced. `seen_items` stops deleted items from coming back, and a 304 must refresh its `last_seen_at`.
- Background offline work (`processPendingArticles`) waits at `whenIdle()` while the user scrolls.
- `images_status`: `deferred` waits for Wi-Fi and is retried. `skipped` is never retried.
- Readability runs in a hidden WebView, because Hermes would block the JS thread.
- Background refresh (`src/feeds/background.ts`) is defined from `index.js`, before `expo-router/entry`, because a headless start never loads routes. It runs only the feed pass; full text needs the extractor WebView, so it finishes on the next launch.
- With "Hide read", the timeline keeps articles read since the last refresh (`keepReadSince`, `src/state/readKeep.ts`), so rows don't vanish mid-session. Bulk "mark read" calls `clearKeptRead()`.
- Reader fonts are inlined as base64, because file:// fonts are blocked. Headings use `var(--body)` so Serif/Sans applies to them.

## Pitfalls hit before

- No swipe actions on list rows. The owner didn't want them, and they broke vertical scrolling. Row actions are on long-press.
- Keep list rows free of per-row animation or gesture state; it caused jank.
- No pull-to-refresh. It fired by accident when scrolling up to the top; refresh is on open/resume and the header button.
- Toasts are global. Screens with bottom controls call `useToastLift(px)`.
- Android clips centred multi-line `Text`. Use `alignSelf: 'stretch'`.
- Saved ignores "Hide read"; otherwise opened saved articles would vanish.
- Re-applying the same route param (`/?feed=12`) needs a nonce (`at=`).
- RN 0.88 has no InteractionManager; defer with `setTimeout`.
- No swiping between articles in the reader; the toolbar's ‹ › arrows move between them. A pager (react-native-pager-view) took over any vertical scroll that drifted a few pixels sideways, and setting `nestedScrollEnabled` on the WebView blocked it completely.
- R8 strips classes that WorkManager creates by reflection, and the app crashes at launch. The keep rules are `extraProguardRules` in `app.json`.
- To test background refresh, background the app, then run `adb shell cmd jobscheduler run -f com.vempus.feedline <id>`. The ID changes after each run (`dumpsys jobscheduler`). A cold start after `am kill` counts as a force-stop, so WorkManager reschedules and the forced job disappears.
- `__tests__/refresh.test.ts` runs the real SQL on `node:sqlite`. Extend it for SQL or refresh changes.
